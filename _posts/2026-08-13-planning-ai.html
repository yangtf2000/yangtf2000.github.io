摘摘要

在规划设计业务中，可规模化应用的 AI 技术已覆盖从资料获取到成果交付的全链条，主要包括：大语言模型 / AIGC（政策检索、大纲构建、报告与文本撰写、润色去"AI 味"）；知识库 + RAG 检索增强（基于真实资料问答、规范查询，抑制数据造假）；多模态生成（文生图 / 图生图，用于分析图、效果图、彩平图、配景）；语音识别与多模态解析（会议纪要转写、踏勘音视频速读）；设计垂直 AI 工具（智能强排、指标计算、规范合规校验）；以及贯穿全程的 AI Agent 智能体（把上述环节编排成自动化流水线，并支持经验沉淀为可复用 Skill）。

这些技术并非取代规划师，而是将重复劳动交由机器、把专业判断留给人员——流程中保留人工确认节点，数据可走国产 / 私有化方案。下文按"业务类型 → 通用工作环节 → 传统技术与 AI 技术对照 → 技术能力总览 → AI Agent 一站式落地"展开，并附两个实操案例。

核心认知：技术门槛已不高，真正的门槛在工作习惯。
上表"实现难易度"一栏多为低—中，说明 AI 工具本身上手并不难、选型也不必反复纠结。推广中更常见的，是一种可以理解的自然惯性——习惯于把活儿攥在自己手里一点点做：宁可花上几天按老办法逐条人工整理数据，也不太愿意先花点时间把思路理清楚、把规则与标准想明白，再交给 AI 去执行。

于是常会听到一些声音：觉得 AI"用处不大""还要花钱""学起来麻烦"。这些话背后，往往不是工具不行，而是还没体会到"把重复劳动交给机器、把专业判断留给人"之后的轻松。

破局点其实很小：不必先成为专家，只要愿意从"我先干完、偶尔让 AI 帮把手"，转向"我先把规则讲清楚，让 AI 出第一稿、我做判断与把关"。这一步迈出去，技术的价值才会真正落到项目里。

四AI 技术能力总览（通用总结：技术 → 适用环节 / 对应传统手段）

① 大语言模型 / AIGC

应用场景：政策检索 · 大纲构建 · 报告撰写 · 去"AI 味"润色

技术：DeepSeek / 豆包 / 通义千问 / 智谱 GLM；长上下文（1M token）、链式思考（CoT）、分章节生成

对应环节：资料获取 · 大纲 · 文本撰写 ｜ 对应传统：人工检索 / Word 逐字撰写

② 知识库 + RAG 检索增强

应用场景：基于真实资料问答 · 规范查询 · 杜绝数据造假（治"幻觉"）

技术：向量数据库语义检索；腾讯 IMA / Cherry Studio（支持私有化部署）

对应环节：资料获取 · 规范校核 ｜ 对应传统：人工翻规范 / 文件夹归档

③ 多模态生成（文生图 / 图生图）

应用场景：分析图 · 效果图 · 彩平图 · 配景补人物

技术：ControlNet 线稿约束 · LoRA 微调（8 分钟训练专属立面）· Seedream / 即梦 · D5 / Lumion 实时 AI 渲染

对应环节：图纸制作 · 效果图 ｜ 对应传统：CAD / SU 建模 / 3ds Max / PS 精修

④ AI Agent 与智能体编排

应用场景：成果自动质检（格式 / 数据 / 术语三校验）· 政策抓取 + PPT 一键生成 · 重复工作批处理

技术：Coze / Dify 工作流编排 · Agent 集群 · Zapier / 集简云跨应用联动

对应环节：贯穿多环节 / 批处理 ｜ 对应传统：人工跨软件搬运与核对

⑤ 语音识别与多模态解析

应用场景：会议纪要转写提炼 · 现场踏勘 · 音视频速读

技术：ASR 语音识别（通义听悟 / 讯飞听见）· 720 云 VR · 大疆航拍解析

对应环节：资料获取（音视频）· 踏勘 ｜ 对应传统：人工记录 / 听写

⑥ 设计垂直 AI 工具（专业模型）

应用场景：智能强排 · 指标计算 · 规范合规校验

技术：小库科技 AI 云 / 设计云 · 建筑学长 SU / Revit 插件实时渲染

对应环节：图纸制作 · 经济测算 · 规范校核 ｜ 对应传统：手工算量 / SU 建模

五用 AI Agent 一站式完成全流程

不必在每个环节单独找工具——AI Agent 可把"资料 → 分析 → 文本 → 出图 → PPT → 校核 → 沉淀"串成一条自动化流水线，由一个人用自然语言驱动。

AI Agent 相比"平时单独用的 AI 工具"的优势

规划师日常已会用豆包、DeepSeek 等大模型做单点辅助（问一句、答一段，再人工复制粘贴到下一个环节）。AI Agent 的不同在于：它能自己规划多步任务、记住上下文、调用代码 / 文件 / 联网 / 专业软件，把原本要人在多个工具间来回搬运的流程，变成"一句话交代、它跑全程"。

平时单独用 AI 工具

  • 一次一答，问答彼此独立，需人记住并搬运中间结果
  • 多环节要反复切换：检索→写→算→出图→PPT 各开各的
  • 长文档 / 大数据易"截断"，跨文件信息难贯通
  • 分析停留在"单题描述统计"，不会主动做交叉、检验
  • 步骤靠人盯，易漏环节、前后口径不一致

用 AI Agent

  • 自主拆解任务、按序执行，全程记忆上下文与中间产物
  • 一个入口串起检索 / 写作 / 计算 / 出图 / PPT / 校核
  • 可调用代码（Python / pandas）处理长表与大规模数据
  • 主动做交叉分析、统计检验与可视化，发现隐藏关系
  • 可定时运行、本地执行，流程标准化、可追溯、合规可控

AI Agent 的关键能力：Skill（经验可沉淀、可复用）

  • 做过一次，即可复用：任何一项工作——无论是一个技术环节，还是整条流程——只要跑通过一次，其需求、经验、要求与模板都能沉淀为一个 Skill，下次直接调用，不必从零再来。
  • 专项 Skill 即"经验工具"：Agent 生态里已有大量针对某一方面的特长 Skill（如"规划文本校核""体检指标标准化""经济测算建模"），开箱即用，相当于把别人的经验变成自己的工具。
  • 自己也能生成：不满足于现成 Skill 时，可把自己的做法一键封装成专属 Skill，形成团队可复用的经验资产——越用越聪明，越沉淀越省力。
案例一：城市更新片区策划报告 AI 生成全流程（零基础八步）
以《城市更新片区策划报告 AI 生成完全指南》中"零基础实战教学"的八步法为例。本案例以豆包的「任务模式」为执行载体：关联本地文件夹作为工作区，AI 按八步依次推进并记忆上下文，逐步输出成果；流程内置三大人工确认节点（大纲 / 核心数据 / 项目清单），确保专业判断与数据真实始终由规划师把关——AI 负责提速，人负责把关。
完整指南：https://yangtf2000.github.io/nav/
执行方式说明：上述八步全部在 豆包的「任务模式」单一任务 内完成，AI 按步骤记忆上下文、每次自动生成不同成果文件。对于数据清洗、专项统计分析等可先用有特长的工具（如 DeepSeek / 豆包数据对话、Kimi 长表、Python Agent）做预处理，将产物作为基础资料放入项目文件夹；豆包读取文件夹内容（本地文件不对外上传），再在任务中统一推进后续撰写与出图。

案例二（重点）：城市体检居民问卷调查的 AI 交叉分析重点
参考住建部城市体检社会满意度问卷与老旧小区改造居民意愿调查框架，对片区 N=400 户居民开展问卷调查（年龄 / 学历 / 居住时长 / 住房身份 + 更新议题重视度 + 参与意愿 + 整体满意度）。传统做法只做单题频率罗列，看不到群体间的结构性矛盾；用 AI Agent（大模型 + Python/pandas 交叉表 + 卡方检验 + 可视化）可一键做交叉比对，发现简单统计忽略的深层问题。
传统简单统计（仅单题频率，易误导）：① 78% 居民"非常重视"加装电梯；② 65% 希望增加养老 / 公共活动空间；③ 整体满意度 3.4 / 5（"还行"）。——三个孤立百分比，看不出谁最需要、谁在发声、均值背后谁被掩盖。

小结：同一份问卷，简单统计只给出"78% 要重视、满意度 3.4"的平面结论；AI 交叉分析（年龄 / 学历 / 居住时长 / 住房身份 × 议题与满意度）则暴露出 需求—决策错配、均值掩盖弱势群体、参与代表性偏差 三类结构性矛盾——这正是靠"逐题数数"永远发现不了、却直接决定更新方案成败的关键。AI 还能顺手产出交叉列联表、卡方显著性与堆叠条形图，让问题一眼可见。
编排为 Agent 流水线：上述两个案例（报告生成八步 + 问卷交叉分析）若由 WorkBuddy / Kimi Work / QoderWork 等 Agent 编排，可串成自动化流水线——规划师只需在关键节点做确认，其余"资料读取 → 指标整理 → 大纲 → 撰写 → 测算 → 交叉分析 → 出图 / PPT"由 AI 驱动，无需在多个工具间来回切换。
